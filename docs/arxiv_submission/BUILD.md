# Build Instructions — KDF arXiv Preprint

The arxiv preprint is composed of three canonical sources:

- [`paper.md`](paper.md) — the clean English body (generated by [`build_paper.py`](build_paper.py))
- [`paper.tex`](paper.tex) — the arxiv-style LaTeX wrapper (preamble + title/abstract + `\input{paper_body.tex}`)
- [`references.bib`](references.bib) — 29 BibTeX entries

Per-section translator's notes remain in `section*_en.md` and `theoretical_foundation_en.md` / `back_matter_en.md` for reference but are **not** included in the final PDF.

## TL;DR — fastest path (Docker-based, matches arxiv's TeX Live environment)

**Requires Docker + pandoc. No local LaTeX install needed.**

```bash
cd docs/arxiv_submission
python build_paper.py          # regenerate paper.md if section_*_en.md changed
./build_arxiv.sh               # full pipeline: pandoc → post-process → xelatex × 2 + bibtex
# → paper.pdf (31 pages, ~190 KB, matches arxiv TeX Live 2026)
```

The script pulls the official `texlive/texlive:latest` image (~3 GB first time),
so the build is reproducible and uses the same engine versions as arxiv's AutoTeX.

**If you have local pandoc + xelatex/bibtex on PATH**: `./build_arxiv.sh --no-docker`.

**If you have no Docker and no local LaTeX**: use Overleaf (Option B below).

## Submission workflow

The three files shipped to arxiv are:

- [`paper.tex`](paper.tex) — XeLaTeX entry point (title / abstract / `\input{paper_body.tex}` / natbib)
- [`paper_body.tex`](paper_body.tex) — body from §1 through Appendix B (generated by `build_arxiv.sh`)
- [`references.bib`](references.bib) — 28 BibTeX entries

Upload these three files as a tarball to arxiv; its AutoTeX picks up the
`%!TEX program = xelatex` magic comment in `paper.tex` and compiles with
`xelatex + bibtex + xelatex × 2` automatically.

## Option A — Local pandoc + LaTeX

### Setup

1. Install pandoc: <https://pandoc.org/installing.html>
   - Windows: `choco install pandoc` or `winget install pandoc`
   - macOS: `brew install pandoc`
   - Ubuntu: `apt install pandoc`

2. Install a LaTeX engine (one of the following):
   - **TeX Live** (most robust, ~4 GB): <https://www.tug.org/texlive/>
   - **MiKTeX** (Windows, auto-installs packages): <https://miktex.org/>
   - **MacTeX** (macOS): <https://www.tug.org/mactex/>

3. Verify installation:
   ```bash
   pandoc --version
   pdflatex --version    # or xelatex / lualatex
   ```

### Build

```bash
cd docs/arxiv_submission
python build_paper.py                        # (re)generates paper.md
pandoc paper.md -o paper_body.tex --wrap=preserve
xelatex paper.tex                            # xelatex recommended for ≤ / ≥ symbols
bibtex paper
xelatex paper.tex
xelatex paper.tex
```

The final `paper.pdf` is produced.

### Notes on pandoc conversion

- The current `paper.md` uses **natural-language citations** (e.g., "(Burt 1992)"), which pandoc will keep as plain text. For numbered `\cite{...}` references via natbib, each citation must be rewritten as `[@burt1992structuralholes]` in the markdown source. This is **optional** for preprints.
- Emoji markers (✅ / ❌ / ⚠️ / 🔧 / ★) require XeLaTeX + a font with emoji support (e.g., Segoe UI Emoji on Windows, Noto Color Emoji on Linux). With pdflatex they will either fail or render as boxes — replace with textual markers `(yes) / (no) / (warning) / (tool) / (star)` as a fallback.
- Tables use markdown pipe syntax and pandoc converts them to `longtable` by default. Some very wide tables (e.g., the Phase X findings table in §7) may need manual `\small` or landscape adjustments.

## Option B — Overleaf (no local setup required)

1. Create a new blank project on <https://www.overleaf.com/>.

2. Upload the following files to the project root:
   - `paper.tex`
   - `paper.md`
   - `references.bib`
   - `build_paper.py` (optional; for regeneration)

3. Convert markdown to LaTeX body:
   - **If Overleaf supports pandoc hooks** (most paid plans do): add a pre-compile hook with `pandoc paper.md -o paper_body.tex`.
   - **Manual path**: run `pandoc paper.md -o paper_body.tex` locally (need pandoc installed only), then upload `paper_body.tex`.

4. Set compiler to **XeLaTeX** in Overleaf → Menu → Compiler.

5. Click "Recompile" — the PDF appears in the preview pane.

## Option C — Tectonic (single-binary, no package install)

[Tectonic](https://tectonic-typesetting.github.io/) is a single-binary LaTeX engine that auto-downloads required packages on first use.

### Setup

- Windows: `winget install tectonic`
- macOS: `brew install tectonic`
- Linux: see <https://tectonic-typesetting.github.io/en-US/install.html>
- Still need pandoc for markdown→LaTeX conversion (see Option A step 1).

### Build

```bash
cd docs/arxiv_submission
python build_paper.py
pandoc paper.md -o paper_body.tex --wrap=preserve
tectonic paper.tex                           # auto-downloads packages, runs bibtex, produces paper.pdf
```

Tectonic's `-X compile` mode handles the bibtex + multi-pass loop automatically.

## Option D — Docker-based build (reproducible)

If you want a fully reproducible build without polluting your system:

```bash
docker run --rm -v "$PWD":/data -w /data pandoc/extra \
  /bin/bash -c "pandoc paper.md -o paper_body.tex && xelatex paper.tex && bibtex paper && xelatex paper.tex && xelatex paper.tex"
```

This uses the `pandoc/extra` image, which bundles pandoc + TeX Live.

## Troubleshooting

### "Undefined control sequence" for emoji characters

With pdflatex, emoji Unicode cannot be rendered. Options:

1. Switch to XeLaTeX (`xelatex paper.tex`).
2. Replace emoji in `paper.md` and re-run `build_paper.py`:
   ```
   sed -i 's/✅/(yes)/g; s/❌/(no)/g; s/⚠️/(warning)/g; s/🔧/(tool)/g; s/★/(star)/g' section*_en.md
   ```
   Then regenerate paper.md and convert.

### Very wide tables overflow the page

The §7 Phase X findings table and the 2×2 Mem0-vs-KDF matrix can overflow. Fixes:

- Wrap table environment with `\begin{landscape} ... \end{landscape}` (requires `pdflscape`).
- Reduce font: `\begin{small} \begin{tabular}{...} ... \end{tabular} \end{small}`.
- Split wide columns onto two lines in the source markdown.

### Japanese characters in comments

The `paper.tex` preamble and main body are pure LaTeX and contain no Japanese. If `paper.md` contains any Japanese (it should not, since `build_paper.py` strips backtranslation blocks), use XeLaTeX + a CJK font:

```latex
\usepackage{fontspec}
\usepackage{xeCJK}
\setCJKmainfont{Noto Sans CJK JP}
```

### Citations stay as plain text after pandoc

As noted above, `paper.md` uses natural-language citations. To get numbered `\cite{}` output, rewrite each citation as `[@key]` in the section files, where `key` matches an entry in `references.bib`. Example:

- Before: `(Burt 1992)`
- After: `[@burt1992structuralholes]`

Then pandoc will emit `\citep{burt1992structuralholes}` which natbib renders as `[22]` (or similar).

## Regenerating paper.md from section files

Whenever a `section*_en.md` file changes:

```bash
cd docs/arxiv_submission
python build_paper.py
```

This strips translator's notes + Japanese back-translations and emits a clean `paper.md`.

The script logic:

- Finds the first `## ` heading in each file (actual paper content start).
- Drops everything from `## Translator's notes on ...` onward.
- Removes `**日本語バックトランス要約**:` paragraph blocks.
- Concatenates in the `SECTION_FILES` order defined inside the script.

If you add a new section file, update the `SECTION_FILES` list in [`build_paper.py`](build_paper.py).
